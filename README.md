# 婚礼对戒款式库 · 收藏与匹配 MVP

一个可直接用浏览器打开的静态婚礼对戒图鉴，支持按品牌/预算/材质/风格筛选、收藏男戒/女戒候选、生成临时组合，以及记录评论与试戴照片。

## 本地打开

直接双击打开 `index.html` 即可浏览，无需构建、无需后端、无需登录。

> 说明：数据通过 `<script src="data/*.js">` 以全局变量形式加载，因此直接打开 HTML 不会产生 CORS 限制。

## 项目结构

```
index.html              入口页面
styles.css              样式
app.js                  交互逻辑（筛选、收藏、匹配、评论、照片）
data/
  brands.js             品牌数据（window.RINGS_BRANDS）
  rings.js              单款戒指数据（window.RINGS_RINGS）
  pairs.js              推荐组合数据（window.RINGS_PAIRS）
  brands.json           同上，JSON 格式（便于后续后端/脚本处理）
  rings.json
  pairs.json
wedding-ring-assets/    图片资源
  *.png / *.jpg / *.webp  现有官网/实物图
  placeholders/*.svg      缺图款式的结构示意占位图
```

## 数据维护

- 品牌、单款、组合数据分别维护在 `data/brands.json`、`data/rings.json`、`data/pairs.json`。
- 当前同时生成 `data/*.js` 用于页面直接加载；后续如改为后端 API，只需替换 `app.js` 中数据加载方式即可。
- 价格标注为“约 ¥X / 枚”或“约 ¥X–Y / 枚”的为估算或参考价，会随金价、戒围、钻石配置变化；标注“需询价”的款式建议到官网或专柜确认。
- 每条数据均保留 `officialUrl` 与 `sourceUrls`。

### 图片状态字段

`rings.json` 中每个单款的 `imageStatus` 用于说明图片来源，当前合法取值：

- `local`：本地图片（`wedding-ring-assets/` 下的官网/实物图）。
- `placeholder`：本地生成的 SVG 结构示意占位图，仅用于理解款式宽窄/材质/镶钻关系，**不冒充品牌实物图**。

缺图款式统一使用 `placeholder`，页面会以“结构示意”徽章明确标注。

## 功能说明

- **筛选**：在“款式目录”或“推荐组合”页可按预算、品牌、材质、风格、男戒/女戒筛选。
- **收藏**：每个款式卡片有两个按钮——“收藏为男戒候选”和“收藏为女戒候选”。
- **生成组合**：进入“收藏与匹配”页，从男戒候选和女戒候选中各选一枚，右侧会生成临时组合并显示合计价格、材质、官网链接，以及是否超过 ¥100,000 预算；若该组合在 `pairs.json` 中已有推荐，会额外显示系统推荐理由。
- **评论**：点击款式卡片的“评论/照片”即可展开，输入评论后按回车保存。
- **上传照片**：在同一展开区域选择本地图片，图片会被压缩后保存到浏览器 IndexedDB；每款最多保留 8 张。
- **导出 / 导入本地数据**：在“收藏与匹配”页可导出本地收藏、已保存组合、评论和当前筛选状态为 `.json` 文件；也可选择 `.json` 文件导入，支持合并导入或覆盖导入。
  - **注意**：导出**不包含**上传照片，照片仍保留在当前浏览器 IndexedDB 中。
- **清空本地数据**：在“收藏与匹配”页可一键清空收藏、已保存组合、评论和 IndexedDB 照片。清空后不可恢复，请谨慎操作。
- **URL 状态分享**：切换 tab 或调整筛选条件时，URL 会通过 `history.replaceState` 轻量更新，支持 `?tab=`、`?q=`、`?budget=`、`?brand=`、`?material=`、`?style=`、`?gender=`。刷新页面后可恢复浏览状态。收藏、评论、照片等隐私数据不会写入 URL。
- **数据持久化**：收藏与评论保存在 `localStorage`，照片保存在 `IndexedDB`，刷新页面后仍然保留。

## 图片来源与版权

- 优先使用各品牌官网产品图或官方商品页图片。
- 部分无法稳定获取公开图片的款式使用本地生成的 SVG“结构示意”占位图，明确标注“结构示意”，不冒充品牌实物图。
- 图片版权归原品牌或权利人所有；当前仅用于内部选购参考。公开上线前应替换为授权图片、自有图片，或确认可合法使用的公开资源。

## 部署

### GitHub Pages（推荐）

1. 将代码推送到 GitHub 仓库。
2. 仓库已包含 `.github/workflows/pages.yml`，push 到 `main` 分支后会自动部署到 GitHub Pages。
3. 打开仓库页面，进入 **Settings → Pages**。
4. 在 **Build and deployment** 中：
   - **Source** 选择 **GitHub Actions**；
   - 工作流 `Deploy static site to GitHub Pages` 会自动运行。
5. 首次部署完成后，访问地址预计为 `https://cd-cloud.github.io/rings/`。

### Vercel / Cloudflare Pages

1. 选择导入 GitHub 仓库。
2. **Build command** 留空（无需构建）。
3. **Output directory** 使用根目录（`.` 或 `/`）。
4. 直接部署即可。

- **本地数据**：收藏、已保存组合、评论保存在浏览器 `localStorage` 中；清除浏览器数据会丢失这些信息。导出 `.json` 可用于备份，但导出文件**不包含**照片。
